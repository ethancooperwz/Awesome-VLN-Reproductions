# 常见报错与解决

先收集以下信息，通常能快速区分环境、数据和显存问题：

```bash
cd "$STREAMVLN_ROOT"
git rev-parse HEAD
python --version
python -m pip check
python -c 'import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available())'
nvidia-smi
```

## 1. `ModuleNotFoundError: habitat` 或 `habitat_baselines`

原因通常是没有激活环境、Habitat-Lab editable install 失效，或安装了错误版本。

```bash
conda activate streamvln
cd /path/to/habitat-lab
python -m pip install -e habitat-lab
python -m pip install -e habitat-baselines
python -c 'import habitat, habitat_baselines; print("OK")'
```

StreamVLN 配套的是 Habitat-Lab 0.2.4，不要直接换成最新版。

## 2. `No module named habitat_extensions`、`model` 或 `utils`

官方评测脚本依赖从项目根目录解析本地模块。确认当前目录正确：

```bash
cd "$STREAMVLN_ROOT"
test -f streamvln/streamvln_eval.py
```

如果直接从其他目录调用脚本，可能触发导入路径问题。

## 3. `libGL.so.1`、EGL 或显示相关错误

服务器应使用 Habitat-Sim 的 `headless` 构建，并保持日志环境变量：

```bash
export MAGNUM_LOG=quiet
export HABITAT_SIM_LOG=quiet
```

`libGL.so.1` 缺失属于系统动态库问题，需要管理员安装对应 OpenGL/EGL runtime。不要用设置假的 `DISPLAY` 来掩盖错误。

## 4. FlashAttention 导入失败或 `undefined symbol`

常见原因是 wheel 与 Python、PyTorch、CUDA 或 C++ ABI 不匹配。先检查：

```bash
python -c 'import torch; print(torch.__version__, torch.version.cuda)'
python -c 'import flash_attn; print(flash_attn.__version__)'
```

环境基线是 Python 3.9、PyTorch 2.1.2；预编译包名中的 `cp39`、`torch2.1` 和 `cxx11abiFALSE` 必须与环境一致。重新装 torch 后也要重新安装 FlashAttention。

## 5. `CUDA out of memory`

每个 torchrun 进程都会加载完整模型。可按顺序处理：

1. 确认 GPU 没有其他残留进程；
2. 将 `--nproc_per_node` 降为实际可用卡数；
3. 保持“一进程一卡”，不要让多个 rank 挤在同一张卡；
4. 关闭 `--save_video` 只能减少 CPU 内存和磁盘压力，通常不能解决模型显存不足。

`num_frames`、`num_history` 会影响上下文，但随意减小也会改变实验设置和指标，不能再称为严格复现。

## 6. 找不到 scene、`.glb` 或 `.navmesh`

典型报错来自目录多套了一层，或 episode 中的 scene ID 没有对应资产。正确结构应类似：

```text
data/scene_datasets/mp3d/17DRP5sb8fy/17DRP5sb8fy.glb
data/scene_datasets/mp3d/17DRP5sb8fy/17DRP5sb8fy.navmesh
```

检查符号链接和实际文件：

```bash
readlink -f data/scene_datasets/mp3d
find data/scene_datasets/mp3d -name '*.glb' | head
find data/scene_datasets/mp3d -name '*.navmesh' | head
```

## 7. 找不到 `val_unseen.json.gz`

`config/vln_r2r.yaml` 默认查找：

```text
data/datasets/r2r/{split}/{split}.json.gz
```

因此 `--eval_split val_unseen` 对应的文件必须是：

```text
data/datasets/r2r/val_unseen/val_unseen.json.gz
```

不要保留成 `data/datasets/R2R_VLNCE_v1/...`，也不要误用旧版 R2R 数据与 v1-3 checkpoint 混跑。

## 8. `unrecognized arguments: --episode_ids`

官方当前 `streamvln_eval.py` 没有 episode 筛选参数。删除该参数即可跑全量评测；如果只想可视化少量案例，需要使用已经实现该功能的本地 fork，或自行修改 episode 过滤逻辑。

先以本地帮助信息为准：

```bash
python streamvln/streamvln_eval.py --help
```

## 9. 分布式/NCCL 初始化失败

检查可见 GPU 数和进程数一致：

```bash
CUDA_VISIBLE_DEVICES=0,1 torchrun --standalone --nproc_per_node=2 ...
```

同一节点同时跑多个任务时可能端口冲突，可显式指定不同端口：

```bash
torchrun --standalone --master_port=29517 --nproc_per_node=2 ...
```

如果日志显示某个 rank 先因数据或 OOM 退出，其他 rank 的 NCCL 报错往往只是连锁反应，应向前查找第一条 traceback。

## 10. `result.json` 为空、最后没有聚合结果或 JSON 损坏

只有所有 rank 正常完成并汇总后，最后一条才包含 `sucs_all` 等字段。检查：

```bash
tail -n 100 results/<run>/eval.log
tail -n 3 results/<run>/result.json
```

多进程会向同一个 JSONL 文件追加结果；强制终止可能留下半行。不要直接在损坏文件上继续正式评测。先备份，校验每行 JSON，再决定恢复或换新输出目录。

## 11. 结果明显低于论文

依次核对：

- 是否使用 v1-3 checkpoint 和 R2R_VLNCE v1-3 数据；
- 是否拉取了包含 `num_history` 修复的最新代码；
- 参数是否为 `num_history=8`、`num_frames=32`、`num_future_steps=4`；
- split 是否为 `val_unseen`；
- 是否跑完全部 episode，而不是少量调试样本；
- 是否把 JSON 中 0–1 的比例误当成百分数；
- 是否出现大量 500 步超时、碰撞或未生成合法动作。

指标仍异常时，保存 commit、环境文件、完整命令、日志尾部和聚合 JSON，再到[官方 Issues](https://github.com/InternRobotics/StreamVLN/issues)检索相同问题。

## 12. 视频无法生成

先确认 FFmpeg：

```bash
ffmpeg -version
export IMAGEIO_FFMPEG_EXE=/usr/bin/ffmpeg
```

视频会显著增加运行时间和磁盘占用。优先完成不带 `--save_video` 的数值评测，再单独跑可视化任务。
