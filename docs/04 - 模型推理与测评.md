# 模型推理与测评

## 1. 评测流程

```text
语言指令 + MP3D 场景
        ↓
Habitat 生成 RGB-D 观察
        ↓
StreamVLN 生成动作序列
        ↓
Habitat 执行动作并更新观察
        ↓
STOP 或达到 500 步 → 计算 NE / OS / SR / SPL
```

执行前请完成[环境配置](02%20-%20环境配置.md)和[数据集准备](03%20-%20数据集准备.md)，并从 StreamVLN 根目录运行所有命令。

## 2. 先做启动检查

```bash
conda activate streamvln
cd "$STREAMVLN_ROOT"

test -f checkpoints/StreamVLN-v1_3/config.json
test -f data/datasets/r2r/val_unseen/val_unseen.json.gz
test -d data/scene_datasets/mp3d

python streamvln/streamvln_eval.py --help
```

如果最后一条命令能打印参数列表，说明项目导入和 argparse 阶段正常。

## 3. 单 GPU 评测

先用单卡确认模型能加载并跑通 Habitat：

```bash
mkdir -p results/r2r_val_unseen_v13_single

CUDA_VISIBLE_DEVICES=0 \
MAGNUM_LOG=quiet \
HABITAT_SIM_LOG=quiet \
torchrun --standalone --nproc_per_node=1 \
  streamvln/streamvln_eval.py \
  --model_path checkpoints/StreamVLN-v1_3 \
  --habitat_config_path config/vln_r2r.yaml \
  --eval_split val_unseen \
  --output_path results/r2r_val_unseen_v13_single \
  --num_history 8 \
  --num_frames 32 \
  --num_future_steps 4
```

这仍然会跑完整个 split，不是快速单元测试。看到 `episode start`、动作输出和每个 episode 的指标，便说明主链路已跑通，可以终止后换多卡正式评测。中止时建议先按一次 `Ctrl+C`，等待各进程退出。

## 4. 双 GPU 后台评测

```bash
mkdir -p results/r2r_val_unseen_v13_full

nohup env \
  CUDA_VISIBLE_DEVICES=0,1 \
  MAGNUM_LOG=quiet \
  HABITAT_SIM_LOG=quiet \
  PYTHONUNBUFFERED=1 \
  torchrun --standalone --nproc_per_node=2 \
  streamvln/streamvln_eval.py \
  --model_path checkpoints/StreamVLN-v1_3 \
  --habitat_config_path config/vln_r2r.yaml \
  --eval_split val_unseen \
  --output_path results/r2r_val_unseen_v13_full \
  --num_history 8 \
  --num_frames 32 \
  --num_future_steps 4 \
  > results/r2r_val_unseen_v13_full/eval.log 2>&1 &

echo $! > results/r2r_val_unseen_v13_full/launcher.pid
```

GPU 数量改变时，`CUDA_VISIBLE_DEVICES` 中的卡数必须和 `--nproc_per_node` 相同。每个进程会各加载一份模型，然后分担 episode。

## 5. 监控进度

```bash
tail -f results/r2r_val_unseen_v13_full/eval.log
nvidia-smi
ps -fp "$(cat results/r2r_val_unseen_v13_full/launcher.pid)"
```

结果文件是 JSON Lines：前面每行是一条 episode，正常结束时最后追加一条聚合结果。查看最终结果：

```bash
tail -n 1 results/r2r_val_unseen_v13_full/result.json \
  | python -m json.tool
```

聚合字段对应关系：

| JSON 字段 | 指标 |
| --- | --- |
| `sucs_all` | SR |
| `spls_all` | SPL |
| `oss_all` | OS |
| `ones_all` | NE |
| `length` | 汇总的 episode 数 |

SR、SPL、OS 在 JSON 中是 0–1 的比例；与论文百分数比较时要乘 100。例如 `0.564` 对应 56.4%。

## 6. 结果是否完整

不能只看进程退出码。还应确认：

1. 日志结尾没有 traceback、CUDA OOM 或 NCCL 错误；
2. `result.json` 最后一条同时含 `sucs_all`、`spls_all`、`oss_all`、`ones_all` 和 `length`；
3. episode 数与数据 split 一致；
4. 指标接近[实验结果与分析](06%20-%20实验结果与分析.md)中的官方参考值。

官方实现会在同一个 `result.json` 里追加写入，多进程意外中断后原地续跑可能产生不完整行或重复统计。正式复跑时优先使用新的输出目录；若要恢复，先备份结果文件并检查每条 JSON，而不是直接覆盖。

## 7. 保存视频

官方脚本支持 `--save_video`，并把 RGB 画面和 top-down map 写到输出目录：

```bash
export IMAGEIO_FFMPEG_EXE=/usr/bin/ffmpeg
mkdir -p results/r2r_visual

CUDA_VISIBLE_DEVICES=0 \
MAGNUM_LOG=quiet \
HABITAT_SIM_LOG=quiet \
torchrun --standalone --nproc_per_node=1 \
  streamvln/streamvln_eval.py \
  --model_path checkpoints/StreamVLN-v1_3 \
  --habitat_config_path config/vln_r2r.yaml \
  --eval_split val_unseen \
  --output_path results/r2r_visual \
  --num_history 8 \
  --num_frames 32 \
  --num_future_steps 4 \
  --save_video
```

注意：官方当前版本没有 `--episode_ids` 参数，上述命令会为所有 episode 保存视频，耗时且占空间。如果本地 fork 新增了 episode 筛选，可先确认：

```bash
python streamvln/streamvln_eval.py --help | grep episode_ids
```

只有输出中确实存在该参数时，才可追加类似 `--episode_ids 115 1191 214` 的选项。

## 8. 可视化案例如何解读

- 成功案例：轨迹在目标 3 m 内执行 `STOP`，`success=1`。
- “从未到达”：`oracle_success=0`，通常是感知、指令对齐或动作规划失败。
- “到过但没停”：`oracle_success=1`、`success=0`，说明停止判断失败。
- 成功但 SPL 低：到达了目标，但有明显绕路或反复转向。

分析失败案例时，建议同时记录指令、俯视轨迹、最终距离、动作步数和生成文本，不能只看最终一帧。
