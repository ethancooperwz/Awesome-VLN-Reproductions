# StreamVLN 论文介绍

## 1. 论文信息

- 论文：**StreamVLN: Streaming Vision-and-Language Navigation via SlowFast Context Modeling**
- arXiv：[2507.05240](https://arxiv.org/abs/2507.05240)
- 代码：[InternRobotics/StreamVLN](https://github.com/InternRobotics/StreamVLN)（旧组织地址 `OpenRobotLab/StreamVLN` 会重定向）
- 项目主页：[streamvln.github.io](https://streamvln.github.io/)
- 任务：连续环境中的视觉语言导航（VLN-CE）

本文档以官方仓库当前公开的代码和 **R2R_VLNCE v1-3** checkpoint 为准。旧版 R2R_VLNCE v1 的数据或旧提交可能得到明显不同的结果。

## 2. StreamVLN 解决什么问题

VLN 智能体接收自然语言指令和连续的第一视角图像，需要不断输出低层动作，直到到达目标位置。例如：

> 离开卧室，经过走廊，在餐桌旁停下。

传统 Video-LLM 导航方法通常在每一步重新编码整段历史。随着轨迹变长，视觉 token 和推理延迟持续增长；如果只保留少量历史帧，又容易丢失“走过哪里、看见过什么”等长期信息。

StreamVLN 将导航过程建模为多轮对话，并把上下文分成两条流：

1. **Fast-streaming dialogue context**：用固定大小的滑动窗口保存最近若干轮对话，并复用 KV cache，负责当前动作的快速生成。
2. **Slow-updating memory context**：在窗口切换时整理较早的视觉历史，作为长期记忆；可使用基于三维体素邻近关系的 token pruning 去除空间冗余。

这种设计让上下文长度和计算开销保持有界，同时保留长程导航所需的信息。

## 3. 输入、输出与动作空间

仿真评测中，模型读取：

- 一条语言导航指令；
- 当前及历史 RGB 观察；
- 深度、相机位姿和内参（主要用于几何记忆/空间裁剪）；
- 已生成的对话和动作上下文。

模型输出由四种离散动作组成：

| 动作 | 含义 | Habitat 配置 |
| --- | --- | --- |
| `↑` | 前进 | 0.25 m |
| `←` | 左转 | 15° |
| `→` | 右转 | 15° |
| `STOP` | 结束当前 episode | 成功距离阈值为 3 m |

官方评测命令保留 `num_future_steps=4` 以对齐发布配置。当前评测代码会解析模型生成文本中的动作并由 Habitat 顺序执行；这个参数并不是推理阶段强制截断输出为 4 个动作的硬上限。

## 4. 训练数据与训练流程

官方训练分为两阶段：

1. 使用 R2R、RxR 等 oracle 轨迹进行第一阶段微调；
2. 用第一阶段模型收集 DAgger 纠错轨迹，再混合导航数据和通用视觉语言数据继续训练。

主要数据来源包括：

- R2R、RxR、EnvDrop 导航数据；
- 约 15 万条转换到 VLN-CE 格式的 ScaleVLN 子集；
- DAgger 在线纠错轨迹；
- LLaVA-Video-178K、ScanQA/SQA3D 和 MMC4 等通用多模态数据。

论文中的基础模型是以 Qwen2-7B 为语言模型的 LLaVA-Video 7B。论文报告完整训练约消耗 1500 A100 GPU 小时，因此本仓库优先记录“使用公开 checkpoint 复现评测”，完整训练只作为进阶方向。

## 5. 评测数据与指标

主要基准是基于 Matterport3D 场景的 R2R-CE 和 RxR-CE，重点考察 `val_unseen`，即在训练中未出现过的室内场景上泛化。

| 指标 | 含义 | 趋势 |
| --- | --- | --- |
| NE | 结束位置到目标的最短路径距离（米） | 越低越好 |
| OS | 轨迹中是否曾进入成功半径 | 越高越好 |
| SR | 执行 `STOP` 时是否位于成功半径内 | 越高越好 |
| SPL | 用路径效率加权后的成功率 | 越高越好 |
| nDTW | 预测轨迹与参考轨迹的归一化相似度，RxR 常用 | 越高越好 |

OS 高但 SR 低通常意味着智能体曾到达目标附近，却没有及时停止；SR 高但 SPL 偏低则说明绕路较多。
